# 设计取舍

这份文件记录「为什么这样做」，不重复规则内容。规则本身在 `profile.json`，看那份就够。

## 一、为什么用 JSON 而不是 YAML

最初选的是 YAML，理由是人写起来舒服。改判的原因是工程约束：Node 没有内置 YAML 解析器，要「零依赖」就得自己写一个子集解析器，而 YAML 的缩进歧义、多行块、引号转义会反复咬人。对非程序员来说，一个悄悄解析错的配置比一个当场报错的配置危险得多。

JSON 的代价是长句要拆成字符串数组、不能写注释。换来的三件事：

1. `JSON.parse` 是语言内置的，脚本不会因为解析器本身出错。
2. `$schema` 让编辑器边写边报错，不必等到运行构建。
3. 数组元素的 diff 是逐行颗粒的，能看清到底改了哪一句。

## 二、为什么不让 agent 现场裁决冲突

最早的写法是把冲突留给模型：「如果两条规则冲突，按情况判断」。这不可复现——同一句话在两个 agent 上会得到相反结果，档案的权威性随之消失。

现在的做法是两条：

1. **用 `appliesTo` 分流**。真正的冲突往往不是逻辑矛盾，而是适用范围不同。事实类交付物要删除无法查证内容，方法论类交付物本身就是推理，两者根本不在同一个标签下。
2. **显式登记**。真的无法用标签分开的，写进 `conflictsWith` 与 `resolution`，构建时校验。登记过的冲突不需要裁决，只需要查表。

代价是要多花时间想清楚冲突的性质。收益是执行结果可复现。

## 三、为什么「硬性底线」不单独建一个文件

用户的原始需求列了七个维度，其中「硬性底线」和「不可接受行为」看起来最像独立章节。但它们不是新数据：

- 硬性底线 = 所有 `severity: block` 的条目
- 不可接受行为 = 每条规则里的 `antiPattern`

如果为它们各建一份文件，同一件事就有两个版本。改一处忘另一处，两周后两份内容开始互相矛盾——这是档案类文档最常见的死法。

所以这七个维度落成五个`category`加两个视图。视图由脚本生成，永远与事实源一致。

## 四、为什么把上限写死在脚本里

规则只会增加，这是不可逆的熵。没有上限的档案，三年后会膨胀到没人读，而没人读的档案等于不存在。

三个数字都有具体来源：

| 上限 | 值 | 依据 |
| --- | --- | --- |
| 规则条数 | 40 | 超过这个量，人无法在一次阅读中建立整体印象 |
| `AGENTS.md` 行数 | 130 | 官方对指令文件的建议是 200 行以内，本档案刻意更严 |
| 粘贴块字数 | 1200 | 再长就没人愿意每次粘贴 |

超限时构建失败，而不是打印警告。警告会被忽略，失败不会。

## 五、粘贴块为什么从 600 字放宽到 1200 字

最初定 600 字，实测写不下：19 条 block 规则的 `statement` 合计 636 字，加上编号与标题已超过 900。硬压到 600 只能靠截断语句，截断后的规则会失去可执行性。

放宽到 1200 的同时，我删掉了一段「元规则」摘要——因为它和 block 列表里的 R-META-01、R-META-02、R-TRUST-01 说的是同一件事，属于我自己造成的重复。**先删重复，再调上限**，顺序不能反过来。

到 v0.2.0，block 增至 21 条，粘贴块 1100/1200 字，余量只剩 100 字。这个余量是故意的：它意味着下一条 block 规则必须先把某两条合并、或把某条降级成 `warn`，而不是习惯性地「再调一次上限」。

## 六、为什么不解决「agent 可能不遵守」这个问题

解决不了。指令文件在多数客户端里只是上下文，不是配置；模型可以选择忽略。

能做的只有三件事，都做了：

1. 把文件写短（130 行、1200 字）。
2. 把能强制的 4 条标出来，给出 hook 思路。
3. 把验证做成 14 个场景的人工核对表。

在 README 与 `docs/enforcement.md` 里明确写「不保证遵守」，比含糊承诺更负责。

## 七、尚未解决的问题

- **跨语言漂移**。档案是中文的，如果某个 agent 的内部推理以英文为主，细微语义可能失真。当前策略是声明「以中文回复」，但无法验证它是否真的按中文语义执行。
- **私密档案的合并没有实现**。`profile.local.json` 的合并规则写进了加载协议，但 `build.mjs` 目前不读它。原因是公开仓库里不应出现合并逻辑处理私密数据的痕迹；实际使用时由 agent 手动合并。
- **判断型规则的锚点太少**。当前只有两条规则带 `anchor`。锚点是我自己写的样例，未必代表你的真实偏好。
- **自检清单依赖人工**。14 个场景跑一遍约需 25 分钟，容易被跳过。
