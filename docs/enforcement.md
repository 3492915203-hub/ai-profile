# 强制性：哪条真的拦得住，哪条只是君子协定

这份文件要说清一件不讨喜的事：**写进 `AGENTS.md` 不等于会被执行。**

## 一、三类指令文件的实际地位

`CLAUDE.md` 与 `AGENTS.md` 在多数客户端里是以「上下文」形式送入模型的，属于建议而非配置。Anthropic 的文档对此写得很直白：它被当作上下文处理，不保证严格遵循；要「无论模型怎么决定都要拦住某个动作」，官方指向的是 `PreToolUse` hook。[已验证：Claude Code memory 文档明确区分「CLAUDE.md 是 advice, not a lock」与「PreToolUse hook 用于阻止动作」。]

所以本档案给每条规则标了 `enforceable` 字段，取值为三层：

| 取值 | 含义 | 能不能真的拦住 |
| --- | --- | --- |
| `hook` | 可以写成 `PreToolUse` 或等价钩子，在工具调用前拦截 | 能，但需要你在客户端配置钩子 |
| `lint` | 可以用脚本静态检查（如扫描仓库里有没有密钥） | 能发现，但不能阻止 |
| `prompt` | 只能靠模型自觉 | 不能 |

## 二、本档案的分级结果

标注为 `hook` 的 4 条，是真正能被技术拦住的：

| ID | 规则 | 拦截点 |
| --- | --- | --- |
| `R-DEL-03` | 覆盖同名文件前先比 md5 | 写入工具调用前校验目标哈希 |
| `R-DEL-05` | 不主动删除用户已有文件 | 删除类命令（`rm` / `del` / `Remove-Item`）前拦截 |
| `R-NET-01` | 禁止第三方镜像 | 下载命令里出现镜像域名时拦截 |
| `R-EXT-01` | 对外动作须授权 | 发信、发布、上传类命令前拦截 |

标注为 `lint` 的 1 条：`R-SEC-01`（密钥不入仓），可以用脚本扫描，但只能在提交时发现，无法阻止输入。

其余 25 条都是 `prompt` 级：只能靠模型读到并愿意遵守。

`R-NET-02`（网络失败先自测）属于这一级，而且**没法升级成 hook**：hook 能检查「命令里有没有镜像域名」，却看不出「有没有先测另一条通道」，因为这件事发生在命令之外。它只能靠自检清单第 13 条人工核对。

## 三、hook 的最小实现思路

不同客户端的 hooks 配置格式不同，但结构一致：在工具调用前匹配命令，命中就返回阻断信号。WorkBuddy 与 Claude Code 的 hooks 配置同构，字段为 `matcher`（工具名正则）、`type`（`command` 或 `prompt`）、`timeout`。[已验证：本机 hooks 配置与 Claude Code 同构，本机已有可用的 `PreToolUse` 拦截脚本先例。]

一个可用的拦截骨架（bash，伪代码级，需按你的客户端调整输出格式）：

```bash
#!/usr/bin/env bash
# 读入 stdin 的 JSON，取出将要执行的命令
cmd=$(cat | tr -d '\n')

# R-NET-01：第三方镜像
if echo "$cmd" | grep -qE 'ghfast\.top|gh-proxy\.com|ghproxy\.'; then
  printf '{"continue":false,"stopReason":"违反 R-NET-01：禁止第三方镜像下载"}\n'
  exit 0
fi

printf '{"continue":true}\n'
```

**两个致命细节**（本机实测踩过）：

1. `stdout` 必须是 JSON。输出纯文本会被**静默丢弃**，hook 等于没配。
2. 配置在客户端启动时缓存，改完必须**完全退出进程再启动**才生效。

## 四、不要指望 hook 做的事

- hook 拦不住「模型在回答里编造数据」，那属于内容层，不在工具层。
- hook 拦不住「措辞让人不适」，`R-COL-02` 与 `R-COL-03` 只能靠模型读规则。
- hook 写得太宽会拦住正常操作。宁可只拦最危险的 4 条，也不要为了「全覆盖」让工具无法使用。

## 五、所以这份档案的价值在哪

如果 23 条都只是建议，写它干什么？三个理由，都是可观察的：

1. **短文件比长文件更容易被遵循。** 这正是本档案把 `AGENTS.md` 压在 130 行、把粘贴块压在 1200 字以内的原因。
2. **显式引用能让你纠错。** 回答里出现「依据 R-DEL-02」，你可以一句话定位到该改哪条，而不是笼统地说「你做得不对」。
3. **规则可版本化。** 行为变了可以查 `CHANGELOG.md`，而不是靠记忆。

剩下的，交给 `docs/compliance-checklist.md` 里那 14 个场景，人工核对。
