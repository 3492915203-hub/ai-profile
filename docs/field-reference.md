# 字段说明

改 `profile.json` 时对着这张表填。填错的后果写在第 4 列——多数错误会让构建直接失败，而不是悄悄生效。

## 一、规则条目的字段

| 字段 | 必填 | 取值 | 填错会怎样 |
| --- | --- | --- | --- |
| `id` | 是 | `R-类别-序号`，如 `R-DEL-02`；本地条目用 `L-` 开头 | 格式不符或重复，构建失败。**废弃后 ID 永不复用**，否则历史引用会指向另一条规则 |
| `category` | 是 | 七个枚举之一：元规则／事实与表达／交付与文件／获取与外部动作／协作方式／决策原则／工作习惯 | 枚举外的值直接失败。类别是给人做归纳用的，不影响执行 |
| `severity` | 是 | `block`／`ask`／`warn` | 决定 agent 的动作：无条件执行／命中即停／可偏离须说明。写错等于改错了行为强度 |
| `statement` | 是 | ≤ 60 字的一句话 | 超过 60 字会让 `AGENTS.md` 超行数，构建失败。**只写规则本身，不写理由** |
| `comply` | 是 | 字符串数组，每条一个动作 | 空数组构建失败。写成「要专业」「要仔细」这类形容词，规则等于没写 |
| `antiPattern` | 是 | 字符串数组，每条一个具体反例 | 空数组构建失败。反例比正例更能约束行为，别写空泛的「不要犯错」 |
| `rationale` | 是 | 为什么有这条 | 留空构建失败。这是后人敢不敢删改的唯一依据 |
| `appliesTo` | 是 | `factual`／`methodological`／`creative`／`operational` 的子集 | 空或非法值失败。它决定任务类型过滤，填错会让规则在该生效时不生效 |
| `enforceable` | 是 | `hook`／`lint`／`prompt` | 必须在 `docs/enforcement.md` 的分级表里对得上，否则那份表就是假的 |
| `judgment` | 否 | `true` | 标了 `true` 却没给 `anchor`，构建失败。判断型规则没有样例就无法执行 |
| `anchor` | 否 | `{ good, bad }` 两段片段 | 只在 `judgment: true` 时需要。样例要短，一段话即可 |
| `source` | 是 | 用户确认该条的日期，或 `draft` | 标 `draft` 表示还没经用户确认，需人工复核 |
| `since` | 是 | `YYYY-MM-DD` | 格式错失败。用于判断规则的新旧 |
| `status` | 是 | `active`／`deprecated`／`retired` | 只有 `active` 进生成物。改状态而不删条目，是保留历史引用的唯一办法 |
| `reviewBy` | 否 | `YYYY-MM-DD` | 过期只提醒不失败。没有这个日期，条目会永久沉睡 |
| `conflictsWith` | 否 | 规则 ID 数组 | 声明了却没有 `resolution`，构建失败；指向不存在的 ID 也失败 |
| `resolution` | 否 | 裁决说明 | **禁止写「由 agent 判断」**。写了等于没写，且下次执行结果不可复现 |
| `onUncertain` | 否 | `ask`／`best-effort`，仅 block 有效 | 用于「必须做但信息不足」的中间态：是停下来问，还是先按最保守方式做 |

## 二、meta 的字段

| 字段 | 必填 | 说明 | 填错会怎样 |
| --- | --- | --- | --- |
| `version` | 是 | 语义版本，必须与 `VERSION` 文件一致 | 不一致构建失败 |
| `updated` | 是 | `YYYY-MM-DD` | 格式错失败 |
| `owner` | 是 | 公开别名，**不填真名** | 填真名等于把身份信息写进公开仓库 |
| `language` | 是 | 如 `zh-CN` | — |
| `languageNote` | 是 | 语言策略说明 | 缺失会让英文 prompt 场景下 agent 擅自换语种 |
| `exemption` | 是 | 固定 `none` | 改成其他值构建失败。block 不可豁免是硬设定 |
| `exemptionNote` | 是 | 豁免说明 | — |
| `precedence` | 是 | 1 到 5 级，从高到低 | 超过 5 级失败。这张表越长越像判例法，反而无法裁决 |
| `precedenceNote` | 是 | 优先级表的适用范围 | 不写清范围，agent 会拿它去覆盖 block 级规则 |
| `trust.sources` | 是 | 白名单来源 | 空数组失败。没有白名单，防注入规则就是空话 |
| `redaction` | 是 | 脱敏判定线与私有文件名 | — |
| `breaking` | 是 | 破坏性变更记录数组 | 可为空数组，但字段必须在 |

## 三、limits 的字段

| 字段 | 当前值 | 含义 |
| --- | --- | --- |
| `rules` | 40 | 规则总数上限。到了就必须归档，不能加 |
| `agentsLines` | 130 | `AGENTS.md` 行数上限。官方对指令文件的建议是 200 行以内，这里刻意更严 |
| `compactChars` | 1200 | 粘贴块的非空白字符数上限。超了就粘不进聊天框 |

改这三个数字之前先想清楚：上限放宽一次，就会有第二次。

## 四、示例条目的字段

| 字段 | 说明 |
| --- | --- |
| `id` | `EX-01` 格式 |
| `title` | 一句话情境标题 |
| `situation` | 当时发生了什么，**必须脱敏**：不出现真名、地名、机构名 |
| `wrong` | 错误做法，写具体动作 |
| `right` | 正确做法，写具体动作 |
| `rules` | 关联规则 ID 数组，必须都存在 |

## 五、写 `statement` 的四条经验

1. **一句话只装一个约束。** 「不编造，且要标注引用，且要原创」应拆成三条。
2. **写动作，不写品质。** 「不确定就回答不知道」可执行；「要严谨」不可执行。
3. **能用否定句就用否定句。** 「禁止用第三方镜像」比「优先使用官方来源」更难被绕过。
4. **60 字是硬约束，不是建议。** 写不下说明这条要拆。
